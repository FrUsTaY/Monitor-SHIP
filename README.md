# 🚢 Мониторинг пароходов со спутниковым интернетом

## 📌 Назначение
Приложение предназначено для **непрерывного мониторинга доступности спутникового интернета** на пароходах.  
Оно проверяет IP-адреса модемов, отображает статус каждого судна в реальном времени и ведёт **журнал потерь пакетов** для анализа стабильности связи.

Программа разработана для **администраторов спутниковых сетей** и позволяет:
- Отслеживать доступность десятков судов одновременно.
- Настраивать чувствительность к сбоям.
- Блокировать суда на время обслуживания.
- Сохранять часовую статистику потерь и формировать отчёты по каждому судну за любой период.

## 🚀 Установка и запуск

### Требования
- Python 3.8 или выше (скачать с [python.org](https://python.org))
- Операционная система: Windows, Linux или macOS

### Установка
1. Скачайте все файлы проекта в одну папку.
2. Убедитесь, что Python добавлен в `PATH`.
3. Дополнительных библиотек не требуется – используются только встроенные модули (`asyncio`, `subprocess`, `json`, `os`, `signal`, `time`, `datetime`, `typing`, `platform`).

### Запуск
```bash
python main.py
```

### Упрощённый запуск (без ввода `python` каждый раз)
Создайте файл `start_monitor.bat` в папке с программой и напишите в нём:
```bat
python main.py
pause
```
Теперь можно запускать приложение двойным кликом по `start_monitor.bat`.

## 🔍 Как работает мониторинг

### Архитектура
- **Асинхронный параллельный опрос** – все суда проверяются одновременно (используется `asyncio`). Время одного цикла равно максимальному времени одного ping (по умолчанию 3 сек), а не сумме всех.
- **Интервал между циклами** – задаётся в настройках (по умолчанию 10 сек). Это пауза между завершением одного цикла и началом следующего.

### Логика определения статуса (сглаживание)
Чтобы избежать ложных срабатываний из-за кратковременных сбоев, используются два порога:

- **Offline Threshold** – сколько **последовательных неудачных** проверок подряд нужно, чтобы перевести судно в статус «не в сети». По умолчанию 3.
- **Online Threshold** – сколько **последовательных успешных** проверок подряд нужно, чтобы вернуть судно в статус «в сети». По умолчанию 1.

Эти пороги можно менять в **пункте 8** меню.

### Отображение на экране
При запуске мониторинга экран **очищается** и отображается таблица со статусами всех судов:
- **Зелёный** цвет – судно в сети.
- **Красный** цвет – судно не в сети.
- **Жёлтый** цвет – статус ещё не определён («не проверено»).
- Звёздочка `*` рядом со статусом означает, что статус изменился в последнем цикле.

Таблица обновляется каждый цикл, без бесконечного скролла.

## 📝 Логирование

### Ежечасное логирование
- Во время работы мониторинга для каждого судна подсчитывается количество успешных и неудачных ping-запросов за текущий час.
- В **начале каждого часа** (по системному времени) вычисляется процент потерь:
  ```
  потеря = (неудачи / (удачи + неудачи)) * 100
  ```
- Запись добавляется в файл `logs/logs_ГГГГ-ММ-ДД.log` в формате:
  ```
  ===== 2026-06-24 14:00 - 15:00 =====
  Записано: 2026-06-24 14:05
  Славянка - потеря пакетов 12.5%
  Бикин - потеря пакетов 3.2%
  ...
  ==================================================
  ```
- Если судно было заблокировано или не было попыток – пишется `нет данных`.
- Каждый день создаётся отдельный файл.

### Логирование при остановке мониторинга (неполный час)
Если вы остановили мониторинг (Ctrl+C) до наступления нового часа, программа **спросит**:
```
Мониторинг остановлен. Сохранить лог за текущую сессию? (y/n):
```
- При ответе `y` – создаётся запись с реальным интервалом работы (например, `14:23 - 14:45 (неполный час)`).
- При ответе `n` – лог не сохраняется.

### Выгрузка отчёта по судну за период
В **пункте 9** меню вы можете:
1. Выбрать судно из списка.
2. Указать период (вручную или выбором за последние 7/30 дней).
3. Программа соберёт все записи из лог-файлов за указанный период и сформирует отдельный файл:
   ```
   logs/report_Амурское_20260620_20260624.txt
   ```
   В отчёте будут все часовые интервалы с процентами потерь в хронологическом порядке.

## 🔒 Блокировка судов

Если судно уходит на ремонт или плановое обслуживание, его можно **заблокировать**:
- В **пункте 4 (Редактировать судно)** выберите судно и пункт **«Переключить блокировку»**.
- Заблокированное судно **не участвует в проверках** (пропускается в мониторинге и ручных обновлениях).
- В списке судов (пункт 1) у заблокированного судна отображается значок `🔒`.
- В **пункте 5 (Заблокированные суда)** можно увидеть список всех заблокированных и разблокировать любое из них.

## ⚙️ Настройки мониторинга (пункт 8)

В этом пункте меню можно изменить три глобальных параметра:

| Параметр | Описание | По умолчанию |
|----------|----------|--------------|
| **Интервал между циклами** | Пауза между окончанием одного цикла проверки и началом следующего (сек). | 10 |
| **Порог перехода в "не в сети"** | Сколько последовательных неудач нужно для перехода в офлайн. | 3 |
| **Порог возврата в "в сети"** | Сколько последовательных успехов нужно для возврата в онлайн. | 1 |

Настройки сохраняются в файл `config.json` и не теряются при перезапуске.

## 🗂️ Формат данных судов (ships.json)

```json
[
    {
        "name": "Славянка",
        "connections": [
            {"satellite": "AM5", "ip": "82.194.162.22"},
            {"satellite": "E103", "ip": "195.161.122.218"}
        ],
        "status": "в сети",
        "blocked": false
    }
]
```

- `name` – название судна.
- `connections` – массив спутников, каждый с названием и IP-адресом.
- `status` – текущий статус (заполняется автоматически).
- `blocked` – флаг блокировки (`true`/`false`).

После запуска мониторинга:

3. Проверьте создание логов – дождитесь смены часа или остановите мониторинг с сохранением.
4. Попробуйте выгрузить отчёт по судну за текущий день.
